Рабочий цикл этапа workaly. Задача: $ARGUMENTS

1. Контекст. Прочитай `AGENTS.md`, хвост `docs/progress.md`, актуальный
   документ этапа из `docs/` и раздел «Общее правило приёмки изменения»
   в `docs/roadmap.md`. Критерии приёмки не переиначивай.
2. Реализация. Выполни задачу минимальными изменениями, соблюдая
   инварианты из `AGENTS.md`.
3. Проверки. Выполни применимые проверки из `AGENTS.md` и сохрани
   фактические результаты: команда, exit code, ключевые строки вывода.
4. Независимое ревью. Вызови субагента `reviewer` через инструмент
   запуска субагентов. Передай ему: полный `git diff`, критерии приёмки
   этапа и вывод проверок из шага 3. Перед вызовом убедись, что reviewer
   разрешён в каталоге субагентов этой сессии.
5. Итерации. Исправь обоснованные замечания (не более 2 итераций), после
   каждой — повтори проверки из шага 3 и передай обновлённый diff и вывод
   reviewer'у повторно.
6. Атомарные коммиты. Только после успешных проверок и вердикта `APPROVED`:
   разбей изменения на логически завершённые единицы (связанные исходники
   и тесты одной функции — вместе; независимые исправления — раздельно;
   не создавай искусственные коммиты на каждый файл). Для каждой единицы:
   проверь diff и `git status`, повтори применимые проверки, добавь в индекс
   только конкретные файлы единицы (без `git add .` / `git add -A`, если в
   рабочем каталоге есть посторонние изменения), создай коммит в формате
   conventional commits. Если исправление замечаний состоит из нескольких
   независимых изменений — раздели их на коммиты так, чтобы каждое
   промежуточное состояние было проверено работоспособным. Если безопасно
   разделить нельзя — остановись и объясни причину, не создавай фиктивные
   коммиты. Посторонние пользовательские файлы в коммиты не включай.
7. Итог. Сформируй отчёт: изменённые файлы, результаты проверок с
   exit code, вердикт reviewer'а (`APPROVED` или `REQUEST_CHANGES`),
   список созданных коммитов (SHA, сообщение, состав), оставшиеся риски.

Ограничение автоматизации: шаг 4 — инструкция основному агенту, а не
гарантированный механизм. Команда не может принудительно вызвать субагента:
фактический вызов зависит от решения модели и от разрешения `subagent`
у текущего агента. Если вызов не состоялся — явно сообщи об этом и
останови цикл до ручного запуска ревью отдельной сессией с агентом
`reviewer` (или запроса «используй субагента reviewer для ревью diff»).

Push не выполняй. Force push и переписывание истории запрещены.
